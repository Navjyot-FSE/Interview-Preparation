• Policies: JSON document that outlines permissions for users or groups
	AWS managed policies/Customer managed policies/Inline policies

Amazon EC2
---------------------------------------------------------------------------------------------------
EC2 = Elastic Compute Cloud = Infrastructure as a Service
Cloud Web Deplyoment = EC2 + EBS + ELB + ASG

• EC2 Instance: AMI(OS) + Instance Size(CPU + RAM) + Storage(EBS/EFS/Instance store) + Security Groups + EC2 User Data(Bootstrap scripts)
• EC2 User Data: Script launched at the first start of an instance
• EC2 Instance Types:
	• General Purpose: 
		• General purpose instances provide a balance of compute, memory and networking resources, and can be used for a variety of diverse workloads. 
		• These instances are ideal for applications that use these resources in equal proportions such as web servers and code repositories.
		• Use Cases: Applications built on open source software such as application servers, microservices, gaming servers, midsize data stores, and caching fleets.
	• Compute Optimized
		• Compute Optimized instances are ideal for compute bound applications that benefit from high performance processors. 
		• Use Cases: Instances belonging to this category are well suited for batch processing workloads Compute intensive applications.
			Media transcoding
			High performance web servers
			High performance computing (HPC)
			Scientific modeling
			Dedicated gaming servers 
			Ad server engines
			Machine learning inference 
	• Memory Optimized:
		• Memory optimized instances are designed to deliver fast performance for workloads that process large data sets in memory.
		• Use Case: Memory-intensive workloads such as open source databases, 
			In-memory caches
			Real-time big data analytics.
	• Accelerated Computing
		• Accelerated computing instances use hardware accelerators, or co-processors, to perform functions, such as floating point number calculations, graphics processing, or data pattern matching, more efficiently than is possible in software running on CPUs.
		• Use Cases: 
			Generative AI applications, including question answering
			Code generation
			Video and image generation
			Speech recognition
	• Storage Optimized
		• Storage optimized instances are designed for workloads that require high, sequential read and write access to very large data sets on local storage. 
		• They are optimized to deliver tens of thousands of low-latency, random I/O operations per second (IOPS) to applications.
		• Use Cases
			Relational databases (MySQL, PostgreSQL)
			Real-time databases, NoSQL databases (Aerospike, Apache Druid, Clickhouse, MongoDB), 
			Real- time analytics such as Apache Spark.
	• HPC Optimized
		• High performance computing (HPC) instances are purpose built to offer the best price performance for running HPC workloads at scale on AWS. 
		• HPC instances are ideal for applications that benefit from high-performance processors such as large, complex simulations and deep learning workloads.
		• Use Cases
			Computational fluid dynamics (CFD)
			Weather forecasting
			Molecular dynamics.
	• Instance Features
		• Amazon EC2 instances provide a number of additional features to help you deploy, manage, and scale your applications.
	• Measuring Instance Performance
• Security Groups: Firewall attached to the EC2 instance
	• Controls how traffic is allowed into or out of our EC2 Instances.
	• Security groups only contain allow rules
	• Security groups rules can reference by IP or by security group
	• Control of Inbound/Outbound network
	• All inbound traffic is blocked by default
	• All outbound traffic is authorised by default
• Classic Ports to know
	• 22 = SSH (Secure Shell) - log into a Linux instance
	• 21 = FTP (File Transfer Protocol) – upload files into a file share
	• 22 = SFTP (Secure File Transfer Protocol) – upload files using SSH
	• 80 = HTTP – access unsecured websites
	• 443 = HTTPS – access secured websites
	• 3389 = RDP (Remote Desktop Protocol) – log into a Windows instance
• Connect to EC2
	• SSH: Start a terminal into our EC2 Instances (port 22)
	• EC2 Instance Connect: 
		• Connect to your EC2 instance within your browser
		• No need to use key
		• Need to make sure the port 22 is still opened!
		• EC2 Instance Role: link to IAM roles
• EC2 Instances Purchasing Options
	• On-Demand Instances – short workload, predictable pricing, pay by second
	• Reserved (1 & 3 years)
		• Reserved Instances – long workloads
		• Convertible Reserved Instances – long workloads with flexible instances
	• Savings Plans (1 & 3 years) – commitment to an amount of usage, long workload
	• Spot Instances – short workloads, cheap, can lose instances (less reliable)
	• Dedicated Hosts – book an entire physical server, control instance placement
	• Dedicated Instances – no other customers will share your hardware
	• Capacity Reservations – reserve capacity in a specific AZ for any duration

EC2 Storage
---------------------------------------------------------------------------------------------------
• EBS volumes: 
	• Network drives attached to one EC2 instance at a time 
	• Mapped to an Availability Zones 
	• Can use EBS Snapshots for backups / transferring EBS volumes across AZ 
• EC2 Instance Store: 
	• High performance hardware disk attached to our EC2 instance 
	• Lost if our instance is stopped/terminated
• EFS: Multi AZ, Network file system, can be attached to 100s of instances in a region 
• EFS-IA: cost-optimized storage class for infrequent accessed files 
• 3rd party high-performance file systems on AWS
	• FSx for Windows: Network File System for Windows servers 
	• FSx for Lustre: High Performance Computing Linux file system
• AMI: (AMI = Amazon Machine Image)
	• Create ready-to-use EC2 instances with our customizations 
	• AMI are built for a specific region (and can be copied across regions)
	• You can launch EC2 instances from:
		• A Public AMI: AWS provided
		• Your own AMI: you make and maintain them yourself
		• An AWS Marketplace AMI: an AMI someone else made (and potentially sells)
• EC2 Image Builder: Automatically build, test and distribute AMIs

Elastic Load Balancing & Auto Scaling Groups Section
---------------------------------------------------------------------------------------------------
• High Availability vs Scalability (vertical and horizontal) vs Elasticity vs Agility in the Cloud
• Elastic Load Balancers (ELB): Managed load balancer
	• Distribute traffic across backend EC2 instances, can be Multi-AZ
	• Supports health checks
	• 4 kinds of load balancers offered by AWS:
		• Application Load Balancer (HTTP / HTTPS only) – Layer 7
		• Network Load Balancer (ultra-high performance, allows for TCP) – Layer 4
		• Gateway Load Balancer – Layer 3
		• Classic Load Balancer (retired in 2023) – Layer 4 & 7
• Auto Scaling Groups (ASG)
	• Implement Elasticity for your application, across multiple AZ
	• Scale EC2 instances based on the demand on your system, replace unhealthy
	• Integrated with the ELB

Amazon S3
---------------------------------------------------------------------------------------------------
• Buckets vs Objects: global unique name, tied to a region, there is no directory its key with /, key is full path of object
• S3 security: IAM policy, S3 Bucket Policy (public access), S3 Encryption
	• User-Based
		• IAM Policies – which API calls should be allowed for a specific user from IAM
	• Resource-Based
		• Bucket Policies – bucket wide rules from the S3 console - allows cross account
		• Object Access Control List (ACL) – finer grain (can be disabled)
		• Bucket Access Control List (ACL) – less common (can be disabled)
	• S3 bucket security use cases
		• Public Access - Use Bucket Policy
		• User Access to S3 – IAM permissions
		• EC2 instance access - Use IAM Roles
		• Cross-Account Access – Use Bucket Policy
	• Bucket settings for Block Public Access: These settings were created to prevent company data leaks
• S3 Websites: S3 can host static websites and have them accessible on the Internet
• S3 Versioning: Multiple versions for files, prevent accidental deletes
• S3 Replication: Same-region or cross-region, must enable versioning
• S3 Storage Classes
	• Amazon S3 Standard - General Purpose: Used for frequently accessed data, Low latency and high throughput
	• Amazon S3 Infrequent Access (IA): Less frequently accessed, but requires rapid access.
		• Amazon S3 Standard-Infrequent Access (IA)
		• Amazon S3 One Zone-Infrequent Access
	• Amazon S3 Glacier Storage Classes: Low-cost object storage meant for archiving/backups
		• Amazon S3 Glacier Instant Retrieval
		• Amazon S3 Glacier Flexible Retrieval
		• Amazon S3 Glacier Deep Archive
	• Amazon S3 Intelligent Tiering
• S3 Durability and Availability
	• High durability (99.999999999%, 11 9’s)
	• 99.99% availability
• S3 Encryption
	Server-Side Encryption
	Client-Side Encryption
• IAM Access Analyzer for S3: Ensures that only intended people have access to your S3 buckets
• Snow Family: import data onto S3 through a physical device, edge computing
• Edge Computing: 
	• Process data while it’s being created on an edge location(A truck on the road, a ship on the sea, a mining station underground)
	• These locations may have limited internet and no access to computing power
	• We setup a Snowball Edge device to do edge computing
• AWS Storage Cloud Native Options
	• Block: EBS, Instance Store
	• File: EFS
	• Object: S3, Glacier
• OpsHub: Desktop application to manage Snow Family devices
• AWS Storage Gateway: Hybrid solution to extend on-premises storage to S3
	File, Volumes, Tapes <===AWS Storage Gateway===> EBS, S3, Glacier

Databases
---------------------------------------------------------------------------------------------------
• Relational Databases - OLTP: 
	• RDS (Relational Database Service) - Managed DB service for DB use SQL
		• Create databases in the cloud that are managed by AWS, You cant SSH
		• Postgres, MySQL, MariaDB, Oracle, Microsoft SQL Server, IBM DB2, Aurora
	• Aurora
		• Aurora is a proprietary technology from AWS (not open sourced)
		• PostgreSQL and MySQL are both supported as Aurora DB 
		• Aurora storage automatically grows in increments of 10GB, up to 128 TB
• RDS Deployments: Read Replicas, Multi-AZ, Multi-Region
	• Read Replicas: Scale the read workload of your DB
	• Multi-AZ: Failover in case of AZ outage (high availability)
	• Multi-Region (Read Replicas): Disaster recovery in case of region issue, Local performance for global reads
• In-memory Database: ElastiCache -  Reduce load off databases for read intensive workloads (like Redis)
• Key/Value Database: 
	• DynamoDB (serverless)
		• Fully Managed Highly available with replication across 3 AZ
		• NoSQL database - not a relational database
		• Single-digit millisecond latency – low latency retrieval
		• DynamoDB is a key/value database
	• DAX (cache for DynamoDB)
		• Fully Managed in-memory cache for DynamoDB
		• 10x performance improvement
		• DAX is only used for and is integrated with DynamoDB, while ElastiCache can be used for other databases
	• DynamoDB – Global Tables
		• Make a DynamoDB table accessible with low latency in multiple-regions
		• Active-Active replication (read/write to any AWS Region)
• Warehouse - OLAP: Redshift (SQL)
	• Redshift is based on PostgreSQL, but it’s not used for OLTP its OLAP(online analytical processing)
	• Columnar storage of data (instead of row based)
	• Massively Parallel Query Execution (MPP), highly available
	• SQL interface for performing the queries
	• Automatically provisions and scales data warehouse underlying capacity
	• Use cases: Reporting, dashboarding applications, real-time analytics…
	• Amazon Redshift Spectrum 
		• Run queries directly against S3 without worrying about loading entire data from S3 into a data warehouse. Scale compute and storage independently.
		• Athena vs Redshift Spectrum
			• Amazon Athena - Quick ad-hoc queries without provisioning a compute cluster (serverless)
			• Amazon Redshift Spectrum - is recommended if you are executing queries frequently against structured data
• Hadoop Cluster: EMR(Elastic MapReduce)
	• Helps creating Hadoop clusters (Big Data) to analyze and process vast amount of data
	• Clusters can be made of hundreds of EC2 instances
	• Use cases: data processing, machine learning, web indexing, big data…
• Athena: Query data on Amazon S3 (serverless & SQL)
	• Serverless query service to analyze data stored in Amazon S3
	• Uses standard SQL language to query the files
	• Use compressed or columnar data for cost-savings (less scan)
	• Use cases: Business intelligence / analytics / reporting, analyze & query VPC Flow Logs, ELB Logs, CloudTrail trails, etc
• QuickSight: Dashboards on your data (serverless)
	• Serverless machine learning-powered business intelligence service to create interactive dashboards
	• Integrated with RDS, Aurora, Athena, Redshift, S3
• DocumentDB: “Aurora for MongoDB” (JSON – NoSQL database)
• Amazon QLDB(Quantum Ledger Database): Financial Transactions Ledger (immutable journal, cryptographically verifiable)
• Amazon Managed Blockchain: managed Hyperledger Fabric & Ethereum blockchains
• Glue: Managed ETL (Extract Transform Load) and Data Catalog service
• Database Migration Service: DMS
	• Quickly and securely migrate databases to AWS, resilient, self healing
	• The source database remains available
	• Supports: Homogeneous, Heterogeneous both migrations 
• Neptune: graph database (Social Network)
• Timestream: time-series database (Share Price with time, Train location at what time, GPS trackings saves etc)
• Amazon Keyspaces - Serverless Cassandra-compatible Column-family database

Other Compute
---------------------------------------------------------------------------------------------------
• Docker: 
	• Container technology to run applications
	• Docker Repositories
		• Public: Docker Hub
		• Private: Amazon ECR
• ECS: 
	• Run Docker containers on EC2 instances
	• You must provision & maintain the infrastructure (the EC2 instances)
	• Has integrations with the Application Load Balancer
• Fargate:
	• You do not provision the infrastructure (no EC2 instances to manage) – simpler!
	• Serverless offering, AWS just runs containers for you based on the CPU/RAM you need
• ECR: 
	• Private Docker Images Repository
	• This is where you store your Docker images so they can be run by ECS or Fargate
• EKS
	• Allows you to launch managed Kubernetes clusters on AWS
	• Containers can be hosted on: EC2 instances or Fargate (Serverless)
• What’s serverless?
	• Serverless is a new paradigm in which the developers don’t have to manage servers anymore… 
	• Serverless does not mean there are no servers…, it means you just don’t manage / provision / see them
• Batch: run batch jobs on AWS across managed EC2 instances
	• Fully managed batch processing at any scale
	• Batch will dynamically launch EC2 instances or Spot Instances
	• Batch jobs are defined as Docker images and run on ECS
• Batch vs Lambda 
	• Lambda: 
		• Time limit 
		• Limited runtimes 
		• Limited temporary disk space 
		• Serverless 
	• Batch: 
		• No time limit 
		• Any runtime as long as it’s packaged as a Docker image 
		• Rely on EBS/Instance store for disk space 
		• Relies on EC2 (can be managed by AWS)
• Lightsail: predictable & low pricing for simple application & DB stacks
	• Great for people with little cloud experience!
	• Use cases:
		• Simple web applications (has templates for LAMP, Nginx, MEAN, Node.js…)
		• Websites (templates for WordPress, Magento, Plesk, Joomla)
		• Dev / Test environment
• Lambda Summary
	• Lambda is Serverless, Function as a Service, seamless scaling, reactive
	• Lambda Billing:
		• By the time run x by the RAM provisioned
		• By the number of invocations
	• Language Support: many programming languages except (arbitrary) Docker
	• Invocation time: up to 15 minutes
	• Use cases:
		• Create Thumbnails for images uploaded onto S3
		• Run a Serverless cron job
• API Gateway: expose Lambda functions as HTTP API
	• Fully managed service for developers to easily create, publish, maintain, monitor, and secure APIs
	• Serverless and scalable
	• Supports RESTful APIs and WebSocket APIs
	• Support for security, user authentication, API throttling, API keys, monitoring.

Deploying and Managing Infrastructure at Scale
---------------------------------------------------------------------------------------------------
• CloudFormation: (AWS only) [or Teraform]
	• Infrastructure as Code, works with almost all of AWS resources
	• Repeat across Regions & Accounts
	• CloudFormation + Infrastructure Composer
		• We can see all the resources
		• We can see the relations between the components
• Beanstalk: (AWS only)It is Managed service, a developer centric view of deploying an application on AWS
	• Platform as a Service (PaaS), limited to certain programming languages or Docker
	• Deploy code consistently with a known architecture: ex, ALB + EC2 + RDS
	• Just the application code is the responsibility of the developer
	• Three architecture models: 
		• Single Instance deployment: good for dev 
		• LB + ASG: Great for production or pre-production web applications 
		• ASG only: Great for non-web apps in production (workers, etc..)
	• Support for many platforms: Go, Java SE, Java with Tomcat, .Net on IIS, Node.js, PHP, Python, Ruby, Single/Multi Container Docker, Pre-configured Docker
	• Health Monitoring
		• Health agent pushes metrics to CloudWatch
		• Checks for app health, publishes health events
• CodeDeploy (hybrid): Deploy & upgrade any application onto servers (Deploy code onto servers)
• CodeCommit: Store code in private git repository (version controlled)
• CodeBuild: Build & test code in AWS
• CodePipeline: Orchestration of pipeline (from code to build to deploy)
• CodeArtifact: Store software packages / dependencies on AWS
• Systems Manager (SSM - Services Systems Manager) (hybrid): Patch, Configure and Run commands at scale
	• We need to install the SSM agent onto the systems we control
	• Installed by default on Amazon Linux AMI & some Ubuntu AMI
	• Thanks to the SSM agent, we can run commands, patch & configure our servers
	• SSM Session Manager (& SSM Agent)
		• Allows you to start a secure shell on your EC2 and on-premises servers
		• No SSH access, bastion hosts, or SSH keys needed
		• No port 22 needed (better security)
• AWS CDK: Define your cloud infrastructure using a programming language
	• The code is “compiled” into a CloudFormation template (JSON/YAML)
	• You can therefore deploy infrastructure and application runtime code together
	• Great for Lambda functions, Docker containers in ECS/EKS
	• SDK vs CDK
		• AWS SDK - Interact with AWS services after the infrastructure is set up (like uploading a file to S3, interacting with DynamoDB, etc.).
		• AWS CDK - Define and provision infrastructure (like creating an S3 bucket or an EC2 instance) in a programmatic way. The CDK is used for infrastructure management.

Global Infrastructure
---------------------------------------------------------------------------------------------------
• Global Application: Decresed latency, Disaster Recovery, Attach protection (Regions/Edge Locations(PoP)/Availability Zones)
• Global DNS: Route 53 (is Managed DNS)
	• Great to route users to the closest deployment with least latency
	• Great for disaster recovery strategies
	• Standard DNS Records
		• A (IPv4) ==> www.google.com => 12.34.56.78
		• AAAA IPv6 ==> www.google.com => 2001:0db8:85a3:0000:0000:8a2e:0370:7334
		• CNAME (hostname to hostname) ==> search.google.com => www.google.com
		• NS (Name server) => google.com =>	ns-1453.awsdns-45.org
							ns-234.awsdns-18.com
							ns-6316.awsdns-54.co.uk
		• MX (mail exchange) => mail server
	• example.com => AWS resource == Alias (ex: ELB, CloudFront, S3, RDS, etc…)
	• Route 53 Routing Policies
		• Simple: Maps a domain name to (one or more) IP Addresses
		• Weighted: Maps a single DNS name to multiple weighted resources, 10% to A, 30% to B, 60% to C (useful for canary deployments)
		• Latency: Choose the option with minimum latency. Latency between hosts on the internet can change over time.
		• Failover: Active-passive failover.Primary Health check fails (optional cloud Watch alarm) => DR site is used.
		• Geoproximity: Choose the nearest resource (geographic distance) to your user. Configure a bias.
		• Multivalue answer: Return multiple healthy records (upto 8) at random, You can configure an (optional) health check against every record
		• Geolocation: Choose based on the location of the user
• Global Content Delivery Network (CDN): [CloudFront]
	• Replicate part of your application to AWS Edge Locations – decrease latency
	• Cache common requests – improved user experience and decreased latency
	• CloudFront vs S3 Cross Region Replication
		CloudFront: Great for static content that must be available everywhere
		S3 Cross Region Replication: Great for dynamic content that needs to be available at low-latency in few regions
• S3 Transfer Acceleration: Accelerate global uploads & downloads into Amazon S3
• AWS Global Accelerator
	• Improve global application availability and performance using the AWS global network
	• 2 Anycast IP are created for your application and traffic is sent through Edge Locations
	• AWS Global Accelerator (No caching) vs CloudFront (cacheable content)
• AWS Outposts: Deploy Outposts Racks in your own Data Centers to extend AWS services
• AWS WaveLength: Brings AWS services to the edge of the 5G networks (like mobile or anything connected to 5G), Ultra-low latency applications.
• AWS Local Zones: Bring AWS resources (compute, database, storage,…) closer to your users. Good for latency-sensitive applications.
• Global Applications Architecture
	• Single Region, Single AZ
	• Single Region, Multi AZ
	• Multi Region, Active-Passive (Read/Write to active, read from passive)
	• Multi Region, Active-Active (Read/Write to active as all are acitive)

Cloud Integration 
---------------------------------------------------------------------------------------------------
• There are two patterns of application communication
	• Synchronous communications
	• Asynchronous/Event based (decouple your applications)
• SQS: (Queue model)
	• Queue service in AWS
	• Multiple Producers produce msgs(messages are kept up to 14 days).
	• Multiple Consumers share the read and delete messages when done.
	• Used to decouple applications in AWS
	• Standard Queue/FIFO (first-in-first-out) Queue
• SNS: (Pub-Sub Model) [Topics]
	• Notification service in AWS(pub-sub) (create - topic)
	• Subscribers: Email, Lambda, SQS, HTTP, Mobile…
	• Multiple Subscribers, send all messages to all of them
	• No message retention
• Kinesis: (Alternative for Kafka) [Shards]
	• Real-time big data streaming, persistence and analysis
	• Managed service to collect, process, and analyze real-time streaming data at any scale
	• Amazon Kinesis Data Streams: low latency streaming to ingest data at scale from hundreds of thousands of sources
	• Amazon Data Firehose: load Kinesis Data Streams into Amazon S3, Redshift, OpenSearch, etc…
	• Amazon Kinesis Analytics: Run queries against streaming data to analyize the streams
	• Amazon Kinesis Video Streams: Monitor video streams (Example - can detecect Bad words integrating with AI)
• Amazon MQ: managed message broker for ActiveMQ and RabbitMQ in the cloud (MQTT, AMQP.. protocols)
	• When migrating to the cloud, instead of re-engineering the application to use SQS and SNS, we can use Amazon MQ 
	• Amazon MQ is a managed message broker service for ActiveMQ and RabbitMQ.
• Amazon Managed Streaming for Apache Kafka (Amazon MSK) - Managed Kafka Service in AWS

AWS VPC - Virtual Private Cloud
---------------------------------------------------------------------------------------------------
• VPC: Virtual Private Cloud (Regional Based)
	• Private network in AWS, with control of all trafic, private network to deploy your resources
• Subnets: Tied to an AZ, network partition of the VPC (Public/Private subnets)
	• Subnets allow you to partition your network inside your VPC
	• In AWS Route-Tables are used for routing these are associatd with VPC's/Subnets 
		• To define access to the internet and between subnets, we use Route Tables
• Internet Gateway: Internet Gateways helps our VPC instances connect with the internet
	• For Public Subnets
	• At the VPC level 
	• provide Internet Access
• NAT Gateway(AWS managed)/Instances(Self-managed) [Network Address Translation]
	• For Private Subnets
	• give internet access to private subnets for download software updates/patches
• NACL (Network Access Control List): Stateless firewall at VPC, subnet rules for inbound and outbound, rules have priority no's (100 - less, 10 - more) (IPs) 
• Security Groups: Stateful, operate at the EC2 instance level or ENI (IPs + other Security Groups)
• VPC Peering: Connect two VPC with non overlapping IP ranges, nontransitive
• Elastic IP: Fixed public IPv4, ongoing cost if not in-use
• VPC Endpoints: Provide private access to AWS Services within VPC
	• VPC Endpoint Gateway - S3 & DynamoDB
	• VPC Endpoint Interface - the rest (CloudWatch)
• PrivateLink: Privately connect to a service in a 3rd party VPC
• VPC Flow Logs: Network traffic logs 
	• VPC, Subnets, ENI(Elastic Network Interface)
	• ACCEPT or REJECT Logs
• Site to Site VPN: (Public Internet) VPN over public internet between on-premises DC and AWS
	• On-premises: Must use a Customer Gateway (CGW)
	• AWS: Must use a Virtual Private Gateway (VGW)
• Client VPN: (Public Internet)OpenVPN connection from your computer into your VPC
	• Connect from your computer using OpenVPN to your private network in AWS and on-premises
	• Allow you to connect to your EC2 instances over a private IP
• Direct Connect: (Wired) Direct private connection to AWS
• AWS VPN: Encrypted (IPsec) tunnel over internet to onpremises
• Transit Gateway: Connect thousands of VPC and on-premises networks together
• AWS Local Zones: AWS infrastructure to metro areas, Ideal for real-time user engagement like online gaming.
• AWS Outposts: native AWS services, infrastructure, and operating models to on-premises. Suitable for workloads with regulatory or data residency needs.
• AWS Wavelength: AWS infrastructure in mobile service providers data centers at the 5G network edge. Enables ultra-low latency & high-bandwidth applications for mobile & connected devices.

Some Specials
• Elastic Network Interface (ENI) is a virtual network interface in Amazon Web Services (AWS) that allows an EC2 instance to connect to a VPC (Virtual Private Cloud).

Security & Compliance
---------------------------------------------------------------------------------------------------
• Shared Responsibility on AWS
	• AWS responsibility - Security of the Cloud
	• Customer responsibility - Security in the Cloud
	• Shared controls: Patch Management, Configuration Management, Awareness & Training

• Disaster Recovery Strategies
	• Backup and Restore (Low Cost, High Recovery Time)
		• Description: 
			In this model, data is regularly backed up to Amazon S3, Amazon Glacier, or other storage services. 
			In the event of a disaster, the data is restored from the backup and the application is brought back online.
		• Use Case: Suitable for non-mission-critical applications where recovery time is not as urgent.
	• Pilot Light (Medium Cost, Medium Recovery Time)
		• Description: 
			In this strategy, a minimal version of your environment (the "pilot light") is always running in the cloud. 
			This includes the core infrastructure and the basic data needed to recover. 
			In the event of a disaster, you can quickly scale up the pilot light environment to full capacity.
		• Use Case: Useful for applications that require more availability but cannot afford the cost of keeping a fully replicated environment running.
	• Warm Standby (Higher Cost, Faster Recovery)
		• Description: 
			This strategy involves running a scaled-down version of your full environment in AWS, which is always on and available. 
			In case of a disaster, you can scale up the infrastructure quickly to handle full production load.
		• Use Case: Ideal for applications that need to minimize downtime but can tolerate some cost for a smaller running infrastructure.
	• Hot Standby / Multi-Site (Highest Cost, Instant Recovery)
		• Description: 
			The hot standby strategy maintains a fully operational copy of your environment in AWS, fully synchronized with your primary data center. 
			In the event of a failure, traffic is instantly routed to the backup site with minimal interruption.
		• Use Case: Critical applications where zero downtime is essential, such as financial systems, healthcare systems, or e-commerce platforms with heavy customer traffic.
	• Cross-Region Disaster Recovery
		• Description: 
			This strategy involves replicating your infrastructure and data across multiple AWS regions. 
			If one region fails, your workloads can failover to another AWS region with minimal disruption.
		• Use Case: High-availability applications that need to survive regional outages, such as global e-commerce or financial services.
• AWS Elastic Disaster Recovery (DRS): 
	• Quickly and easily recover your physical, virtual, and cloud-based servers into AWS

	• Protect your most critical database (MySql/SQL Server/Oracle)

• Cloud Migration Strategies: The 7Rs
	• Rehost (Lift and Shift): Move applications and data to the cloud with minimal changes, maintaining the same architecture and design.
	• Replatform (Lift and Reshape): Some optimizations for better performance or cost-efficiency during migration without changing the core architecture.
	• Repurchase (Drop and Shop): Replace legacy applications with cloud-native alternatives (e.g., switching to SaaS solutions).
	• Refactor (Rearchitect): Redesign and rebuild applications to fully leverage cloud-native features, such as scalability and flexibility.
	• Retire: Decommission outdated or obsolete applications that are no longer needed or are redundant in the cloud environment.
	• Retain: Keep certain applications on-premises due to specific requirements (e.g., compliance, latency).
	• Rebuild: Completely rebuild applications from scratch using cloud-native services and architectures.
